# 微信长图：S1–S8 转换规则 + 三项排版断言

长图不是网页页面的截图，是同一份 `outline.json` + 同一套 `tokens.css` 换一次 `mode` 重新构建出来的独立产物。画布固定 430 逻辑宽 × `device_scale_factor` 3 = 出图 1290px 宽。

管线顺序：`build.py`（`mode="longpic"`）出 `longpic.html` → `render_longpic.py` 的 `audit()` 三项排版断言 → 全绿才 `render()` 出图 → `verify_qr()` 解码验证二维码 → 人工过目。**任何一项断言不过，`render()` 直接抛 `LayoutError`，不出图，没有"先出一张凑合看看"的选项。**

## S1–S8：从"agent 要理解的规则"变成"组件自带的查表"

这八条规则在早期是需要 agent 手工执行的转换步骤；在本 Skill 里，八条规则全部下沉成了组件的 `mode="longpic"` 分支——调用方只需要 `C.render(name, data, mode="longpic")`，不需要背下这八条规则再手动改 HTML。这里逐条说明规则内容，以及它在代码里具体落在哪个组件。

| | 规则 | 落在哪个组件 |
|---|---|---|
| S1 | 交互归零：删全部按钮，行动入口只留二维码 | `cta-pills`（web）→ `qr-closure`（longpic）替身；`quote-card` 的原文跳转链接在 longpic 模式下也会去掉，只留文字署名 |
| S2 | 断行人工控制：标题手动 `<br>` 断在语义边界，断行尺子是呼吸单位 4–12 字/行，禁孤字行 | 不是组件自动做的，需要写文案时手动断——见下方"呼吸单位"一节 |
| S3 | 左右改上下：议程、编号列、讲者名+头衔一律拆成上下堆叠 | `agenda-rows`（`.act-stack`）、`talk-card`（`.who-stack`）、`terms-list`（`.ri-stack`）、`compare-bars`（图例转到条形上方）、`info-meta`（`.meta-row`）、`speaker-grid`（`.sg-1col`）、`photo-mosaic`（`.pm-1col`）、`hook-grid`（`.pours-1col`） |
| S4 | 长段落两端对齐：`text-align:justify; text-justify:inter-ideograph; text-wrap:pretty` | `.prose`、`keynote-block`、`agenda-rows` 的 `.act-stack .d`、`talk-card` 的 `.hook`——CSS 重置层（`build.py` 的 `_RESET`）里已经全局声明，组件不需要各自重复 |
| S5 | 删掉长图里不成立的内容（依赖交互的、打断阅读流的） | `quote-ticker`（滚动轮播）没有 longpic 替身，直接从 outline 里删除该组件条目，不是隐藏或转静态——长图没有"时间"这个维度，滚动本身不成立 |
| S6 | 放宽画布：390 → 430 逻辑宽 | `build.py` 的 `_BODY_LP`（`body{width:430px}`），与网页版 390 移动优先画布是两套独立的 body 声明 |
| S7 | 品牌元素重新称重：页脚 logo 收小 | `footer-brand` 按 `mode` 切换宽度：网页 104px → 长图 74px |
| S8 | 尾部自带闭环：时间、地点、二维码，缺一不可 | `qr-closure` 组件三个槽位 `qr`/`alt`/`lines` 全部必填（`base.render` 缺槽位直接抛 `SlotMissing`），`lines` 槽位就是承载时间+地点文案的位置 |

## S2 在哪些组件上根本执行不了：`hook-grid`／`section-head`／`talk-card` 的标题吃不进 `<br>`

S2 说"标题手动 `<br>` 断在语义边界"，这句话默认了一个前提——往 `outline.json` 的 `title` 字段里塞一个字面 `<br>`，组件渲染出来会是一个真正的换行。**这个前提对 `hook-grid`、`section-head`、`talk-card` 三个组件不成立**：它们的 `title` 字段渲染时都会经过 `assets/opb/components/base.py` 的 `esc()`（也就是 `html.escape`），字面 `<br>` 会被转义成 `&lt;br&gt;`，原样显示成四个字符，不会产生换行。已用隔离测试实测验证（不是猜测）：

```python
from opb.components import base as C
C.render("hook-grid", {"title": "进门先点一杯酒，<br>全场就知道你想聊什么", "items": [...]}, "web")
# → <h2>进门先点一杯酒，&lt;br&gt;全场就知道你想聊什么</h2>
```

这三个组件的标题字段目前**没有**任何方式接受手动换行——不是配置错了，是渲染路径上没有留这个口子。撞到"标题在 430px 长图画布下自动换成两行、坏断行断言拦下来"这种情况时，唯一能做的是：

1. **改短这句话，让它能在一行里放下**——这是目前唯一可行的解法，不是权宜之计，是当前唯一路径。断点必须落在语义边界（删掉修饰成分，不是砍半个词凑字数），参考"呼吸单位"一节的 4–12 字尺子，单行标题也适用这个宽度直觉。
2. **不要**尝试往 `title` 字段塞 `<br>`、`\n`，或任何期待被当成标签解析的字符——统统会被 `esc()` 原样转义成可见文字，肉眼一眼能看出来渲染错了，但排查起来容易先怀疑是不是构建流程哪里没跑对。
3. 如果这句话再怎么精简都放不进一行（信息量本身就需要两行才装得下），这是组件能力的真实缺口——不要在 `outline.json` 层面硬解，把情况报给人决定是否要给这三个组件加一个"允许标题分行"的数据结构（例如把 `title` 从单一字符串改成字符串数组，每个元素渲染成一个 `<span>`/`<br>` 分隔的行），这是组件代码层面的改动，不是内容问题，不要在没有授权的情况下顺手改共享组件。

`keynote-block`、`terms-list`、`talk-card` 的 `.hook` 字段（正文型文案，不是标题）不受这条限制——它们走的是 S4 的 `text-align:justify` 自然换行，本来就不需要手动 `<br>`，孤字行断言管的是这条路径上的问题，处理方式见下方"呼吸单位"一节和三项排版断言小节，两件事不要混为一谈。

## 呼吸单位：S2 的断行尺子

`references/copy-layer.md` 第 3 节的 wu-mengzhi 三招里，"呼吸单位"定义为中文每行 4–12 字——这条规则和 S2 是同一件事的两面。手工给标题写 `<br>` 断行时：

1. 先按语义找断点（一个完整的意群结束的地方，不是随便数满 N 个字就切）。
2. 检查切出来的每一行是不是落在 4–12 字区间。
3. 落不进这个区间，说明断点选错了地方——**去重新找语义断点，不是把画布拉宽或者把字号缩小来迁就已经选错的断点。**

## 三项排版断言（全绿才出图，一项不过直接拒绝）

判定逻辑在 `assets/opb/audit.js`，`render_longpic.audit()` 调用它拿到 `{bad, orphan, overflow, docOverflow, height}`。

1. **坏断行**：标题类文案的实际渲染行数 > 手工 `<br>` 声明的行数。意味着浏览器在作者没预料到的地方自动换行了，手工断行的意图被打破——必须整改文案，不能让浏览器替作者决定。
2. **孤字行**：末行字符数 <3。单独一两个字挂在段落最后一行是排版事故。
3. **元素溢出**：任何比容器宽的东西，`position:absolute` 或 `overflow:hidden` 的容器豁免（见踩坑 2）。

外加一个文档级兜底：**`docOverflow`**（`document.documentElement.scrollWidth - clientWidth`）超过 2px 容差也算脏，即使前三项数组全是空的。这条兜底是必须的——如果溢出源自己就是被豁免的那个容器（比如氛围层用负值 `inset` 把自己的盒子撑到视口外），逐元素判定会正确地把它排除在外，但 `document.documentElement` 的可滚动宽度依然会变宽，`full_page` 截图会因此整体跟着变宽，三个数组全空、图已经不对了。只看三个数组会漏掉这种"溢出源本身就是被白名单豁免的那个元素"的情况。

## 两处踩坑

**踩坑 1：孤字行探针不能只取"最后一个文本节点"。** 如果段落以 `</b>。` 这种"粗体片段 + 标点"收尾，DOM 里最后一个文本节点可能只有一个字符（那个句号）——只取最后节点会恒报孤字，不管末行实际有多少字。正确做法：用 `TreeWalker` 遍历元素内**全部**文本节点，逐字符用 `Range.getBoundingClientRect()` 取 `rect.top`，按"是否落在末行带内"分类计数，字符属于哪个文本节点不重要，只看它渲染出来的位置。

**踩坑 2：溢出白名单要排除氛围层，否则每次渲染都会被装饰层刷屏式误报。** `atm-layer` 这类装饰性氛围层用 `position:absolute` 把内容摆到视口外制造出血效果，是故意为之的"合法溢出"，不是排版事故。断言必须排除 `overflow:hidden` 或 `position:absolute` 的容器——但只豁免容器**自己**不被记入溢出名单，容器自己的盒子如果比视口还宽，仍然会被 `docOverflow` 兜底抓到（`atm-layer` 组件本身在 2026-07-29 修复过一次真实的这类溢出：`.atm` 曾经自己就是那个用负值 `inset` 出血的元素，没有任何容器为它兜底裁切，longpic 固定 430px 画布下会把 `wrap/section/body/html` 全部撑宽；修法是让 `.atm` 只做裁切窗口——自己贴着容器、`overflow:hidden`，把出血效果移到内层 `.atm-inner` 上，由 `.atm` 自己裁掉）。

## 二维码必须解码验证，不能靠"看起来像"

`render_longpic.verify_qr(png_path)` 用 `cv2.QRCodeDetector().detectAndDecode()` 真实解码，不是肉眼确认"这块黑白方块看起来像个二维码"。三种返回：

| 返回 | 含义 |
|---|---|
| `(True, 内容)` | 解码成功，内容非空 |
| `(False, "未解出二维码内容")` | 图片能读但解不出码——二维码本身有问题，必须重新生成 |
| `(None, "cv2 未装，二维码需人工扫码确认……")` | `opencv` 是 `preflight.py` 里的软依赖，缺失时降级为人工用手机扫一遍确认，**这个降级必须写进 `REPORT.md`**，不能因为 `render()` 本身没报错就假装验证过了 |

## 交付前必须提醒：微信发送要勾「原图」

微信默认压缩图片会让长图里的文字糊掉。`render_longpic.render()` 的输出里固定带这一条提示，交付时必须原样转告发布的人：**微信发送这张长图务必勾选「原图」，不勾选默认压缩，文字会糊。**

## 长宽比超过 1:15，建议按幕次切两张

`render()` 算出 `height_px / width_px` 的比例，超过 15 时会在 `notes` 里给出提示。一张图拉得过长，读者在手机上要滑很久才能看到结尾——按内容的自然幕次（比如"活动介绍"和"讲者阵容"）切成两张独立的长图分开发送。这条是给人的提示，不是硬性拦截，比例超标不会阻止出图，是否切分由人决定。
